# Socket.IO event contract (v3)

Phase 3 replaced the raw engine credentials (`hostToken`, `playerToken`) with a
single **server-backed session token**. The browser holds only `sessionToken`
(48 hex, one per seat per room) plus the `roomId`; every privileged event is
authorised by the session bound to the socket, and raw engine tokens no longer
appear in any payload or ack.

It also replaces the Phase 1 contract (`create-room`, `join-room`, `start-game`,
`generate-number`, `claimfromplayer`, `sm`), which is refused outright with
`LEGACY_EVENT`.

Conventions

- Request/response events use a socket.io **ack callback**. Every ack is
  `{ ok: true, ... }` or `{ ok: false, code, error }`.
- Push events are **room scoped** (`io.to(roomId).emit`) or **private**
  (`io.to(socketId).emit`). There is no global gameplay broadcast anywhere.
- The payload may be omitted (`socket.emit("game:pause", cb)`); the server
  normalises both shapes.
- Every inbound payload must be a plain object of at most 12 fields and ~4 KB.
- Each connection has an event budget (burst 40, refilled 20/s); exceeding it
  returns `RATE_LIMITED`.

## Client -> server

| Event | Payload | Requires | Response |
|---|---|---|---|
| `room:create` | `{ name }` | - | `{ ok, roomId, sessionToken, playerId, role: "host", state, enabledPatterns }` |
| `room:join` | `{ roomId, name }` | - | `{ ok, playerId, sessionToken, role: "player", name, state, snapshot }` (ticket is inside `snapshot`, sent only to this seat) |
| `session:resume` | `{ roomId, sessionToken }` | - | `{ ok, resumed, role, playerId, roomId, sessionId, snapshot }` |
| `session:rotate` | `{ sessionToken }` | - | `{ ok, sessionToken, sessionId }` (the old token dies with this ack) |
| `room:state` | - | in a room | `{ ok, snapshot }` |
| `room:leave` | - | in a room | `{ ok, left }` |
| `game:start` | - | **host** | `{ ok, state, ticketsIssued, snapshot }` |
| `game:call-next` | - | **host** | `{ ok, number, index, remaining }` |
| `game:pause` | - | **host** | `{ ok, state }` |
| `game:resume` | - | **host** | `{ ok, state }` |
| `game:end` | - | **host** | `{ ok, state }` |
| `game:reset` | - | **host** | `{ ok, state, snapshot }` |
| `game:set-autocall` | `{ enabled?, intervalMs? }` | **host** | `{ ok, autoCall, callIntervalMs }` |
| `claim:submit` | `{ pattern }` | in a room | `{ ok, pattern, label, won, name, points, leaderboard, awards }` |
| `chat:send` | `{ text }` | in a room | `{ ok, sent, text }` |

No `game:*` event carries a credential. `hostOnly` checks that **this socket** is
the room's currently-connected host (`room.isHostSocket`); the room it acts on
comes from the socket's session, never from the payload.

`game:call-next` **takes no number**. The draw is decided by the server only.
`claim:submit` **takes no marks, points or winner flag**; those are computed
from the server's ticket and called history.

## Server -> client (push)

| Event | Scope | Payload |
|---|---|---|
| `room:updated` | room | `{ players: [{ id, name, connected, isHost, points }] }` |
| `game:state` | room | `{ roomId, state, calledCount, remaining, lastCall, autoCall, callIntervalMs, enabledPatterns }` |
| `number:called` | room | `{ number, index, remaining }` |
| `ticket:assigned` | **private** | `{ ticket: 3x9 grid }` |
| `claim:result` | room | `{ pattern, label, won, playerId, name, points, leaderboard, awards }` |
| `game:completed` | room | `{ reason, leaderboard, awards }` |
| `chat:message` | room | `{ from, playerId, text, at }` |
| `host:changed` | room | `{ hostConnected }` |
| `room:closed` | room | `{ roomId, reason }` |
| `app:error` | private | `{ code, error }` |

## Identity and authority

- `roomId` is generated by the server (`newRoomId()`, 8 unambiguous characters,
  ~40 bits) - never a user-supplied password.
- A **session token** (48 hex = 24 CSPRNG bytes) is the only credential a
  browser keeps. It is minted at `room:create`/`room:join`, stored in
  `localStorage`, and is the sole proof used by `session:resume`. The database
  keeps `SHA-256(token)` only - a dumped table cannot be replayed, and the
  token never appears in a URL, log line, analytics event or error message.
- The token is scoped to one seat in one room: it unlocks exactly the `playerId`
  it was issued for. Guessing a `roomId` with no live token gets nothing; a
  token from another room is refused (`SESSION_INVALID`).
- **Host authority** is not a bearer token any more. Host commands are accepted
  only from the socket the room currently recognises as its connected host; a
  session that claims `role: host` but no longer matches the room's owner is
  revoked (`host-mismatch`). A disconnected host keeps its seat but not live
  control until it resumes; nothing transfers to an arbitrary player.
- **Expiry** (enforced by the database clock): idle window 7 days, sliding on
  each use; absolute window 30 days from issue. An expired token is revoked on
  the attempt that finds it and can never be revived.
- **Rotation** is explicit (`session:rotate`), never automatic - an automatic
  swap on every resume would make a harmless retry look like theft. Rotating
  retires the old token (replays of it return `SESSION_ROTATED`) and links a
  lineage row.
- **Revocation**: leaving a seat, closing a room, re-issuing for a seat, or a
  host mismatch all revoke the live rows. A revoked token cannot regain access
  to any room.

Claims, chat and every `game:*` action resolve the acting player from the
socket's server-side session; a `playerId` in a payload is never trusted.

## Game states

`WAITING -> RUNNING -> (PAUSED <-> RUNNING) -> COMPLETED -> WAITING (reset)`.
`WAITING -> COMPLETED` and `PAUSED -> COMPLETED` are allowed. Anything else
returns `INVALID_TRANSITION`. Auto-call draws the next number on a server timer
every `callIntervalMs` (default 8000 ms, 500-120000 configurable).

## Error codes

`BAD_PAYLOAD`, `ROOM_EXISTS`, `ROOM_NOT_FOUND`, `ROOM_CLOSED`, `ROOM_FULL`,
`NAME_TAKEN`, `NOT_HOST`, `NOT_PLAYER`, `UNKNOWN_PLAYER`, `INVALID_STATE`,
`INVALID_TRANSITION`, `DRAW_EXHAUSTED`, `UNKNOWN_PATTERN`, `ALREADY_AWARDED`,
`ALREADY_CLAIMED_BY_YOU`, `RATE_LIMITED`, `LEGACY_EVENT`, `INTERNAL`.

Session codes (the browser clears its saved credential on all but `UNKNOWN`):
`SESSION_UNKNOWN`, `SESSION_INVALID`, `SESSION_EXPIRED`, `SESSION_REVOKED`,
`SESSION_ROTATED`.

Durability codes: `PERSIST_FAILED` (the write did not commit, so nothing was
announced and the client may retry the intent) and `RECOVERY_REQUIRED` (the
room is frozen because its durable state could not be trusted; no further
authoritative events flow until an operator intervenes).

## Breaking changes from v1 (what the browser had to give up)

| v1 | v2 | why |
|---|---|---|
| user-typed room password (`create-room {room}`) | server-generated `roomId` (`room:create {name}`) | a password chosen by a host was also the room's only capability |
| `generate-number {room, no}` - the browser drew the number | `game:call-next` - an intent | the client must not decide the draw |
| `claimfromplayer {data, n, p}` - the browser reported its own win and score | `claim:submit {pattern}` - server verifies | claims were fabricated in the tab |
| `sm {message, n}` - the browser chose the display name per message | `chat:send {text}` - sender from session | chat identity was spoofable |
| `room-joined`, `update-players`, `game-started`, `number-announced`, `rm`, `claimcome` | acks + room-scoped `room:updated` / `game:state` / `number:called` / `claim:result` / `chat:message` | global `io.emit` leaked other rooms |
| browser generated the ticket (`Math.random`) | server issues one ticket per player, sent privately | 47% of generated tickets broke the column rules |
| 11 claim tiles (early seven, star, 143, pyramid, middle number) | 6 verified patterns | the extras had no server rule; the tiles now say so |

Unknown extra fields on a payload are ignored, not refused; the room a request
acts on always comes from the socket's session, never from the payload.
