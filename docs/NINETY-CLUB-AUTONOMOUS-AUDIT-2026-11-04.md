## Repairs made in this audit

1. `server/db/pool.js` used the unrecognized node-postgres option `idle_timeout_millis`; changed it to `idleTimeoutMillis` so the configured connection cleanup interval is honored.
2. Transaction retry now requires a confirmed rollback. If COMMIT is sent but its response is lost, the wrapper reports `PERSIST_UNKNOWN`, marks the outcome unknown, does not retry, and discards the connection. If rollback itself fails, the connection is discarded and the callback is not retried. Four focused regression tests are in `tests/db-pool-failure.test.js`.
3. `scripts/backup.js` now runs `pg_dump` and reads the backup manifest inside the same exported PostgreSQL MVCC snapshot. The manifest cannot silently describe different rows than the archive when writes continue during backup. The concurrency regression is in `tests/backup-snapshot.test.js`.
4. The hardening test assumed that the default `public` schema already contained game migrations. It now creates and closes its own migrated disposable schema, allowing the full suite to pass against a clean database.
5. The security probe expected a removed four-ticket per-player cap and incorrectly treated PostgreSQL's `wasm-unsafe-eval` CSP keyword as JavaScript `unsafe-eval`. Updated assertions reflect the currently implemented shared room ticket capacity and distinguish the CSP directives. It continues to reject unsafe numeric payloads and verifies the real capacity refusal.
6. The first production container boot failed because the final image omitted two shared number-callout files imported by the Sarvam service. Added those explicit runtime files to the image and verified the rebuilt image end to end with the deployment smoke harness.
7. Admin session editing sent `timeZone` in its PATCH body, but the route rejected that field, so saving an attached booking room returned HTTP 400. Added `timeZone` to the route's accepted update fields and a regression test using the full AdminSessions payload. The browser save then succeeded and the public booking-to-room join completed.
8. The moderator account/grant/activity tables overlapped at phone width. Added the existing mobile-card table treatment and visible field labels to those tables; the 390×844 browser capture confirmed legible, non-overlapping rows.
9. The moderator accessibility browser harness assumed a single decorative contrast-incomplete node at 390 px. Current gradient-backed screens make axe report contrast checks as inconclusive at both widths. Corrected the harness to allow only documented axe limitations, still fail on any actual violation or unexpected cause, and emit sample/node counts and reasons. The fresh browser flow passed 30 samples with zero violations; all 342 contrast-incomplete nodes remain visible in the result.
10. The supervised durable-soak runner could record a null process exit code after the two-hour load ended, causing its status JSON to say failed despite the child exit artifact 0 and exact staged `RESULT: PASS`. Added `WaitForExit()` and a process refresh before reading the code. A fresh 60-second supervised 250-client run verified `exitCode: 0`, `wrapperExitCode: 0`, exact pass marker, and container cleanup. The original two-hour run's status artifact is preserved with its null value rather than rewritten.
